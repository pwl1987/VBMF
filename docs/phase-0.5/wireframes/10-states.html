三轴运行时状态 / Three-Axis Runtime State (V0.2 §3): 每个 Channel / Session 同时具有 Lifecycle + Readiness + Health 三轴状态。 Effective Channel Status (对外唯一入口 / channel_health_view.effective_channel_status) 由这三轴 + Aggregation Policy 推导。 本页列出全部 10 个典型状态，作为 Phase 0.5.1 P2-2「Stateful Operator UX」验收参考。
Lifecycle STOPPED · STARTING · RUNNING · STOPPING
Readiness NOT_READY · READY_TO_TAKE
Health HEALTHY · DEGRADED · FAILED · UNKNOWN
→ ECHS HEALTHY · DEGRADED · FAILED · STARTING · STOPPED · UNKNOWN
01
正常 / NORMAL
主备都健康 · 正常运行中 · 所有 Channel HEALTHY
LifecycleRUNNING ReadinessREADY_TO_TAKE HealthHEALTHY CompiledPACKET EffectivePACKET Hot-StandbyHOT
Channel Health View →● HEALTHY
典型场景: 双 SDI 1080p25 + PTP LOCKED · 主备 Capability 对齐 · 平时稳态
02
启动中 / STARTING
Session 启动中 · 资源分配 + Preflight + Capability Check 进行中
LifecycleSTARTING ReadinessNOT_READY HealthUNKNOWN 阶段 / PhasePreflight → 加载 → Init
Channel Health View →● STARTING
典型场景: Operator 点 START → Preflight 跑 → FFmpeg 初始化 → 等第一次 PTS 对齐 · 持续 2-8s · 无观众输出
03
备机未就绪 / BACKUP NOT READY
主播出正常 · 备机正在预热 (WARM 阶段) · 暂时不能接管
LifecycleRUNNING ReadinessNOT_READY HealthHEALTHY BackupWARM 预热中 (84%) Switch RiskELEVATED (由 failover_benchmarks 测量, 不是固定值)
Channel Health View →● HEALTHY
典型场景: 开机 5-15 分钟内 / Backup 重启中 · Operator 看到黄色提醒 · 不阻断播出
04
降级 / DEGRADED
Channel 仍能播 · 但部分子系统降级 · 观众可能感知 (音视频漂移 / 编码质量下降)
LifecycleRUNNING ReadinessREADY_TO_TAKE HealthDEGRADED FailureAV 漂移 +12ms / Clock DEGRADED
Channel Health View →● DEGRADED
典型场景: PTP lost → TIMECODE fallback · 或 AV 漂移超阈值 · 触发 CLOCK_DEGRADED 事件 · Channel 仍 HEALTHY 当本地不感知
05
失败 / FAILED
主备 Source 都 FAILED · Channel 输出中断 · 等待 Operator / 自动恢复
LifecycleRUNNING ReadinessNOT_READY HealthFAILED All SourcesOFFLINE+FAILED RecoveryFiller 兜底播放
Channel Health View →● FAILED
典型场景: 主备 SDI 全部掉线 / 编码器全挂 · Aggregation Rule 3 触发 (Source RG 全部不可用) · Filler 兜底 · Operator 必须立即介入
06
切换中 / FAILOVER (mid-switch)
Auto Failover 进行中 · 从 Primary 切到 Backup · 实测由 failover_benchmarks 记录（不是固定范围）
LifecycleRUNNING ReadinessREADY_TO_TAKE HealthHEALTHY effective_switch_modeFRAME_SWITCH switch_execution_stateEXECUTING FillerACTIVE (按 safety policy)
Channel Health View →● DEGRADED (临时, Policy 推导)
典型场景: Source.A 冻结 → §3.4 决策 FRAME_SWITCH → 执行中 · Filler 按 §8.9 Safety Policy 兜底 · 实际耗时由 failover_benchmarks (p50/p95/p99) 测量 · Chain 2 step 6-8 · SWITCHING 不是 Canonical Enum (V0.2 已锁死)
07
恢复中 / RECOVERY (post-failover)
Failover 完成 · 新主播出稳定 · 但旧 Primary 仍 NOT_READY · Channel DEGRADED
LifecycleRUNNING ReadinessNOT_READY HealthDEGRADED ActiveSource.B (新) Old PrimaryOFFLINE 待重检
Channel Health View →● DEGRADED
典型场景: Failover 完成 30s 内 · 旧 Primary OFFLINE 待 Engineering 重启 · 单点风险 · Operator 应避免新 TAKE
08
停止中 / STOPPING
正在 STOP · 关闭 FFmpeg / 释放资源 · 不可逆中
LifecycleSTOPPING ReadinessNOT_READY HealthUNKNOWN PhaseDrain → Close FFmpeg
Channel Health View →● STARTING (Policy: STARTING/STOPPING → STARTING)
典型场景: Operator 点 STOP · X1 Compiler Drain → FFmpeg 优雅关闭 → 释放 BMD 端口 · 实测由 benchmark 测量, 不写固定范围 · 不可逆 (cancel 必须先 STOP → START 重启) · ECHS=STARTING 是 presentation policy 锁定, 不是 lifecycle 状态
09
已停止 / STOPPED
Session 已停止 · 资源全部释放 · 可以 START 重启
LifecycleSTOPPED ReadinessNOT_READY HealthUNKNOWN Resources全部释放
Channel Health View →● STOPPED
典型场景: 节目结束 · Operator STOP · 24h 录制停 · Channel 显示 STOPPED · 等待下次 START
10
未知 / UNKNOWN
系统无法判断状态 · 通常是监控/通信中断 · 必须告警
LifecycleUNKNOWN ReadinessUNKNOWN HealthUNKNOWN 监控心跳超时 > 30s
Channel Health View →● UNKNOWN
典型场景: Media Agent / Sensor 心跳丢失 · 网络分区 · Channel Health View 直接 UNKNOWN · 触发 ALERT · 不等同于 FAILED (UNKNOWN 不得被吸收为 HEALTHY/DEGRADED)
