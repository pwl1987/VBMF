## 3. 201 条核对总体结论
201 条混含四类，整体结论：
- **绝大多数功能条目与工程规格成立**（与当前已闭环的硬件发现层、真机验收一致）。
- **架构级主张需谨慎**：部分意见把「V0.2 已定义的语义」等同于「Rust 实现已完成」，或把「设计上可替换」等同于「已验证可替换」。

### 3.1 关键修正（二次评审确认）
1. 「Domain 语义全部已实现」**过头** —— V0.2 已定义 Clock / Resource Vector / Media Session / Timecode，但 Rust 实现层未落地这些 Canonical 实体。
2. 「201 条无一与 V0.2 冲突」**证据不足** —— 严谨表述为「已知范围内不冲突」；任何架构级改动仍须经 V0.3 流程拍板（V0.2 LOCK FINAL 不变）。
3. #20 Format「过度设计」**混淆了两种事** —— 冻结契约（定义类型、只填当前用到字段）≠ 完整实现（全部色彩学/编解码）；冻结契约必要，不应被误判为过度设计。

### 3.2 文档结构修订（二次评审）
原 PRD 把主架构 / PRD / EngSpec / Acceptance 混在一处，应拆分为四类独立文档。

- **四层架构**：Canonical Domain → Runtime Contracts/SPI → Runtime Orchestration → Concrete Adapters。
