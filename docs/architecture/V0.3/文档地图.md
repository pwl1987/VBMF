# VBMF V0.3——文档地图

## 1. 权威文档包

`docs/architecture/V0.3/` 是 V0.3 唯一的版本化架构设计文档包。

| 文件 | 职责 | 权威级别 |
|---|---|---|
| `00_总体设计.md` | 产品定位、边界、领域模型、冻结不变量 | 总体架构权威 |
| `01_广播媒体运行时与总体架构详细设计.md` | 运行时、媒体、部署、同步、制作、播出、保护、传输、高可用等详细语义 | 领域详细设计权威 |
| `02_API总体设计.md` | API namespace、语义平面、Command / Query / Event、兼容性、安全和 SDK | API 顶层权威 |
| `03_独立产品基线.md` | Standalone 产品范围、P1-P6、实施 Gate、验收标准 | 产品实施权威 |
| `04_一致性审计与实施映射.md` | V0.2 → V0.3 一致性、阶段映射、迁移审计 | 迁移与实施审计 |
| `文档地图.md` | 文档结构、权威关系、迁移规则 | 文档治理 |

## 2. 权威规则

- `00_总体设计.md` 是 V0.3 架构总入口。
- `02_API总体设计.md` 是 API 顶层语义权威。
- `01_广播媒体运行时与总体架构详细设计.md` 负责广播 Runtime/Fabric 领域详细语义；若存在更具体且经过批准的领域契约，以更具体契约细化，但不得违反总体设计红线。
- `03_独立产品基线.md` 负责 V0.3 Standalone 实施范围和阶段 Gate。
- 母框架仓库继续负责跨仓库所有权、共享上下文、通用事件信封、治理和集成边界。
- 任何 V0.3 文档均不得静默覆盖 V0.2 已冻结的语义契约。

## 3. V0.2 → V0.3 关系

V0.3 是 V0.2 Runtime 基线的产品化演进：

```text
V0.2 冻结 Runtime 语义
        ↓
V0.3 产品边界与领域扩展
        ↓
V0.3 Standalone Runtime 激活
        ↓
专业播出能力 / 一致性 / 母框架集成
```

V0.3 不得通过文档重组改变 V0.2 已冻结的实现语义。

## 4. 实施阶段映射

```text
P0  基线与架构冻结
P1  独立运行时控制平面激活
P2  操作员控制台
P3  运行时加固
P4  广播专业化
P5  一致性与符合性
P6  母框架集成
```

D1-D15 设计阶段必须能够映射到上述 P0-P6 实施阶段；详细映射由 `04_一致性审计与实施映射.md` 维护。

## 5. 迁移与清理规则

旧路径：

```text
docs/architecture/V0.3_API_MASTER_DESIGN.md
docs/architecture/V0.3_BROADCAST_MEDIA_RUNTIME_AND_API_MASTER_DESIGN.md
docs/architecture/V0.3_STANDALONE_PRODUCT_BASELINE.md
```

迁移完成的判定不是“新文件存在”，而必须同时满足：

1. 旧文档中的设计决策全部被新目录覆盖；
2. 重复内容已完成归属整理；
3. 新文件已完成中文化；
4. 技术标识符、API 路径、字段、枚举和代码符号没有被错误翻译；
5. 全仓库搜索不再发现旧路径引用；
6. 旧文件删除后，新目录仍是唯一权威来源。

在上述 Gate 全部通过前，禁止删除旧文件。

## 6. 文件命名规范

V0.3 正文标题及文件名统一采用中文，文件序号用于稳定阅读顺序。

推荐正式名称：

```text
00_总体设计.md
01_广播媒体运行时与总体架构详细设计.md
02_API总体设计.md
03_独立产品基线.md
04_一致性审计与实施映射.md
文档地图.md
```

`README.md` 保留为仓库通用入口文件名，不视为 V0.3 领域文档。
