# VBMF V0.3 设计一致性审计与实施映射

> **状态：V0.3 文档整理审计基线**  
> **审计范围：总体设计、广播运行时详细设计、接口总体设计、独立运行产品基线**

## 1. 审计结论

本次整理后，V0.3 的核心方向保持一致：

```text
专业实时媒体播出系统
        ↓
广播运行时 / 媒体织构
        ↓
输入 → 同步 → 媒体图 → 处理 → 制作 → 播出 → 保护 → 传输 → 输出
        ↓
观察 / 审计 / 恢复
```

三个原始设计文件存在明显内容交叉，但不存在需要推翻顶层产品定位的根本冲突。整理后的职责如下：

| 文档 | 唯一主要职责 |
|---|---|
| `00_MASTER_DESIGN.md` | V0.3 产品定位、总体边界、一级领域、核心不变量、最高级红线 |
| `BROADCAST_MEDIA_RUNTIME_AND_API_MASTER_DESIGN.md` | 广播领域、运行时、部署、同步、制作、播出、保护、传输等详细语义 |
| `API_MASTER_DESIGN.md` | 接口分层、命名空间、命令/查询/事件、幂等、错误、兼容、安全和 SDK 规则 |
| `STANDALONE_PRODUCT_BASELINE.md` | 独立运行产品边界、P1-P6 实施范围、控制台边界、验收 Gate |

## 2. 已解决的一致性问题

### 2.1 产品定位

统一为“专业实时媒体播出系统 / 广播运行时与媒体织构”。编码、转码、网关、切换、调度、录制、接收等均为能力或运行时角色，不再作为平行产品定位。

### 2.2 API 与运行时职责

统一为：

```text
接口
 ↓
控制 / 查询 / 事件
 ↓
运行时
 ↓
媒体平面
```

接口不能取代运行时，控制接口不能承载实时媒体主链路。

### 2.3 P1 范围

原始 Standalone 文档中“完整控制台页面提前进入 P0”的表述容易与后续 P2/P4 冲突。现统一为：

- P1：控制台骨架和运行时控制闭环；
- P2：专业操作控制台；
- P3：缺陷与稳定性；
- P4：录制、事件时间线、预检、能力、同步/延迟、冗余等专业能力。

### 2.4 V0.2 兼容

V0.3 不得通过实施便利偷偷改变 V0.2 冻结语义。P1 保留既有经过验证的命令、幂等、错误和事件语义；V0.3 新契约按版本化流程逐步引入。

### 2.5 Standalone / Integrated

独立与集成两种模式可以更换身份、注册、认证、策略等提供者，但运行时、领域、执行、命令、查询和事件语义必须相同。

## 3. V0.3 红线一致性

以下最高级规则在四份设计中保持一致：

1. 运行时是唯一执行事实源；
2. 观测不等于配置；
3. 语义意图不等于执行计划；
4. 标准模型与厂商模型隔离；
5. UI 不得越过控制接口；
6. 命令、幂等、错误三平面分离；
7. 事件经过明确投影/输出边界；
8. 单一事实所有者；
9. 独立模式和集成模式不分叉运行时；
10. 不因为方便就抽取共享模块；
11. 厂商适配器必须可替换；
12. 不为未来需求提前制造复杂基础设施。

## 4. V0.2 → V0.3 实施映射

| V0.2 冻结语义 | V0.3 位置 | 实施策略 |
|---|---|---|
| Runtime 领域语义 | 总体设计 / 运行时详细设计 | 保持兼容，必要时扩展 |
| Runtime State | 独立产品基线 / P1 | 不静默改变 |
| Command Contract | 接口总体设计 | P1 沿用现有已验证契约 |
| Idempotency | 接口总体设计 | 保持三平面分离 |
| Error Classification | 接口总体设计 | 增加 HTTP 映射，不重写分类 |
| Event Projection | 接口总体设计 / P1 | P1 使用现有投影 |
| Transport Boundary | 总体设计 / 接口总体设计 | 保持控制面与媒体面分离 |
| Health | 独立产品基线 | 进入 P1 闭环 |
| Adapter Boundary | 运行时详细设计 | 保持厂商隔离 |

## 5. P0-P6 与领域设计映射

| 实施阶段 | 主要设计依据 | 结果 |
|---|---|---|
| P0 | 全部 V0.3 设计包 | 冻结基线与映射 |
| P1 | 独立产品基线、接口总体设计、运行时控制语义 | 独立运行控制闭环 |
| P2 | 独立产品基线、制作/播出设计 | 专业操作控制台 |
| P3 | 运行时、观察、连续性设计 | 稳定性和故障恢复 |
| P4 | 同步、制作、播出、录制、高可用设计 | 专业广播能力 |
| P5 | 接口、契约、母框架边界 | 一致性与符合性 |
| P6 | 集成边界 | 母框架集成 |

## 6. 当前明确不进入 P1

以下设计虽然已经进入 V0.3 总体范围，但当前不作为 P1 编码目标：

- 全部顶层接口命名空间；
- 调度器完整实现；
- 放置系统完整实现；
- 工作负载编排系统；
- 分配系统；
- 集群高可用完整实现；
- SSE / WebSocket；
- Prometheus 指标体系；
- 完整事件中心；
- 完整 Incident 子系统；
- 完整录制/回放/时移产品；
- 完整专业切换台；
- 母框架集成；
- AI 能力；
- 大型共享 SDK。

它们属于 V0.3 后续阶段，不得因为接口已经冻结就提前实现。

## 7. P1 唯一核心闭环

```text
启动
 ↓
独立运行时就绪
 ↓
健康查询
 ↓
运行时查询
 ↓
命令提交
 ↓
控制面执行
 ↓
运行时状态变化
 ↓
事件投影
 ↓
幂等重放
 ↓
正常关闭
```

只有这一闭环真实通过后，才进入 P2。

## 8. 文档维护规则

- 本目录是 V0.3 版本设计包的唯一事实源；
- 新增设计必须首先判断应该进入哪一份文档；
- 同一语义只能有一个主要权威文档；
- 其他文档只能引用或约束，不得复制后产生第二份事实；
- 修改冻结红线必须走版本化设计决策；
- V0.3 文档不得依赖母框架仓库才能阅读或理解；
- 旧根目录 V0.3 文档只有在全仓引用检查通过后才能删除。
