# VBMF V0.3——独立产品基线

> **状态：实施基线**  
> **版本：V0.3**  
> **定位：VBMF 独立运行、Web 操作及后续母框架集成的产品边界与实施验收基线**

## 1. 目标

V0.3 将 VBMF 从 V0.2 Runtime 基线推进为能够独立启动、独立操作、独立验收，同时可以在未来无语义分叉地接入母框架的专业实时媒体播出系统。

VBMF 不等待母框架完成后才可使用。

```text
独立模式：浏览器 → VBMF Web 控制台 → 控制接口 → VBMF Runtime → Adapter / Hardware
集成模式：上层平台 → VBMF 集成边界 → VBMF Runtime → Adapter / Hardware
```

两种模式必须共享同一套 Domain、Runtime、Command、Query、Event、Health 和 Execution 语义。

## 2. VBMF 的规范所有权

VBMF 负责：

- 广播会话与 Runtime 执行；
- Source / Input / Signal / Port 及运行时状态；
- Pipeline / MediaGraph 执行；
- Switch / Failover / Redundancy；
- Clock / Synchronization / Media semantics；
- Runtime Health / Watchdog / Recovery；
- Hardware / Vendor Adapter boundary；
- Runtime Control / Query / Event。

VBMF 不负责：

- 母框架本身；
- 企业统一平台；
- CMS/MAM 业务资产事实库；
- 新闻业务事实；
- AI / Knowledge 事实；
- 全局身份、组织、权限事实；
- 全局搜索、通知、任务中心；
- Universal Media SDK。

## 3. Standalone 是一级产品模式

Standalone 不是 debug mode，必须支持：

1. 单机及局域网测试；
2. 工程部署；
3. 广播 Runtime 独立运行；
4. 无母框架环境验收；
5. 故障诊断与运维。

最小组成：

```text
VBMF
├── Web 控制台
├── Control API
├── Local Configuration
├── Runtime Query
├── Command Dispatch
├── Event Projection
├── Health / Diagnostics
└── Broadcast Runtime
    ├── GStreamer
    ├── FFmpeg
    ├── DeckLink
    └── OS / Network
```

独立启动不得强制依赖母框架、业务平台、直播平台、新闻系统或 AI 平台。

## 4. P1 控制台边界

P1 只提供可工作的产品骨架：

- Runtime 首页；
- Health；
- Device / Source 基础观察；
- Session 基础观察；
- 核心 Command 入口；
- Event / Diagnostics 基础观察；
- Engineering 信息。

完整 Dashboard、Sources、Sessions、Switcher、Outputs、Recording、Incidents、Graph/Preflight、AVSync/Latency、Redundancy 等专业体验分阶段进入 P2/P4。

浏览器只能通过 Control / Query / Event 边界工作，不得直接调用 GStreamer、FFmpeg、DeckLink SDK、Rust 内部对象或内部存储。

## 5. P1 核心：独立运行时控制平面激活

P1 不是“实现所有 V0.3 API”，而是让已有 Runtime、Control Plane、Query、Command、Idempotency 和 Event Projection 在 Production Standalone 模式真正工作。

必须形成：

```text
Process Start
 → Standalone Boot
 → Runtime READY
 → GET /health
 → GET /api/v1/runtime
 → POST /api/v1/commands
 → Command Accepted / Executed
 → Runtime State Change
 → GET /api/v1/runtime
 → GET /api/v1/events/projection
 → Corresponding Event
 → Idempotency Replay
 → ALREADY_APPLIED
 → Clean Shutdown
```

这个 Control Loop Gate 是 P1 的核心验收门，证明系统不是“HTTP 返回 200”，而是真正进入运行时控制闭环。

## 6. P1 不做的事情

P1 明确排除：

- 一次性实现全部 V0.3 namespace；
- Scheduler / Placement / Workload / Allocation 全量实现；
- Cluster / HA 全量实现；
- SSE / WebSocket；
- Prometheus 全量指标体系；
- Incident 子系统；
- 新的 V0.3 10 字段 Command / 7 状态契约替换 V0.2；
- 大规模 Error Model 重构；
- AI 能力；
- 母框架集成。

这些能力必须在对应阶段进入，不能为了“看起来完整”而破坏 P1 的边界。

## 7. V0.2 兼容原则

V0.3 可以通过版本化契约扩展 V0.2，但不得静默改变以下已冻结语义：

- Runtime Domain；
- Canonical Media；
- Runtime State；
- Command Contract；
- Idempotency；
- Error Classification / CommandStatus / IdempotentDispatch 三平面；
- Event Projection；
- API / Transport boundary；
- Health invariants；
- V0.2 architecture red lines。

因此，P1 对 Production 运行路径取消历史上的 503 行为时，必须明确属于 **V0.3 Standalone Control Plane Contract activation**，不是修改 V0.2 历史行为。

## 8. 集成模式

Integrated 可以替换：

```text
Identity Provider
Registry Provider
Authentication Provider
Policy Provider
```

但不得改变：

```text
Domain semantics
Runtime execution
Command semantics
Query semantics
Event semantics
```

## 9. 六类边界

所有新增能力必须首先判断属于：

1. Core / Cross-cutting Contract；
2. Contract / Schema；
3. SDK / Developer Consumption；
4. Control / API；
5. Broadcast Runtime / Domain；
6. Infrastructure / Vendor Adapter。

业务、应用、体验和全局平台能力默认不进入 VBMF Core。

## 10. SDK 原则

`vbmf-sdk` 遵循契约优先、SDK 后置、真实消费者优先：

```text
稳定 L0 Contract
 ↓
Domain Contract
 ↓
OpenAPI / JSON Schema / AsyncAPI
 ↓
Contract Tests
 ↓
Real Consumer Evidence
 ↓
vbmf-sdk
```

SDK 不得成为 Rust 内部接口镜像，也不得暴露 GStreamer、FFmpeg、Vendor SDK 或数据库对象。

## 11. V0.3 红线

1. Runtime 是唯一执行事实源；
2. Observation 不等于 Configuration；
3. Intent 不等于 Execution Plan；
4. Canonical Model 不等于 Vendor Model；
5. UI 不得越权；
6. Command / Idempotency / Error 必须三平面分离；
7. Event 必须单向投影；
8. VBMF 不建立业务内容、AI、用户、组织或全局资产第二事实源；
9. Standalone / Integrated 不得分叉 Runtime；
10. Vendor Adapter 必须可替换；
11. 不因“未来可能需要”提前引入复杂基础设施；
12. V0.2 冻结契约未经版本化流程不得偷偷修改。

## 12. 实施阶段

```text
P0 基线与架构冻结
 ↓
P1 独立运行时控制平面激活
 ↓
P2 操作员控制台
 ↓
P3 缺陷修复与运行时加固
 ↓
P4 广播专业化
 ↓
P5 一致性与符合性
 ↓
P6 母框架集成
```

## 13. P1 完成判定

P1 只有在以下条件同时满足时才能关闭：

- VBMF 可以脱离母框架独立启动；
- Runtime 能进入明确 READY 状态；
- Production Control Plane 已正式接线；
- `/api/v1/runtime` 返回真实 Runtime 快照；
- `/api/v1/commands` 能进入正式执行路径；
- Idempotency 行为保持 V0.2 契约；
- Event Projection 能观察到实际执行事实；
- Web Console 通过正式 API 操作 Runtime；
- 回归测试全部通过；
- Standalone Control Loop Gate 全部通过；
- 具备干净关闭路径；
- 没有引入母框架运行时依赖。
