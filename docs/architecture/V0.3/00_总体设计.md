# VBMF V0.3 — 总体设计

> **状态：LOCKED BASELINE**  
> 版本：V0.3  
> 产品：**Professional Real-Time Media Playout System / 专业实时媒体播出系统 / Real-Time Media Runtime & Fabric**

## 1. 产品定位

VBMF V0.3 是一个专业实时媒体 Runtime/Fabric，其第一性原则职责是保障专业媒体从输入、同步与处理，到制作、播出、保护、传输和输出的可靠 Runtime 生命周期。

编码器、解码器、转码器、网关、切换台、调度器、接收器、录制器和采集硬件都是该产品边界内的 Capability、Workload、Resource 或 Adapter——而非独立的产品身份。

## 2. Runtime 边界
```text
Input / Contribution
        ↓
Clock / Timestamp / Synchronization
        ↓
Media Graph / Processing
        ↓
Production / Switching
        ↓
Playout / Scheduling
        ↓
Broadcast Protection
        ↓
Encode / Mux / Packetize
        ↓
Transport / Gateway
        ↓
Output / Delivery
        ↓
Monitoring / Audit / Recovery
```

这是一个逻辑生命周期。它不要求一台机器、一个进程或一家厂商。

## 3. 主要领域

1. 媒体 I/O
2. 媒体处理
3. 媒体网关（Media Gateway）
4. 媒体图（Media Graph）
5. 同步
6. 制作
7. 播出
8. 广播保护（Broadcast Protection）
9. 传输 / 分发
10. Resource / Workload / Placement
11. 高可用 / 连续性
12. 录制 / 回放 / 时移
13. 可观测性 / 诊断 / 审计
14. Runtime Control / Query / Event
15. 资产 Runtime 集成边界

这些是领域边界，而不是要求创建十五个服务。

## 4. 核心架构模型
```text
Runtime
 ├── Node / Device / Adapter
 ├── Resource / Capability
 ├── Workload / Placement / Allocation
 ├── Source / Input / Signal / Stream
 ├── Pipeline / MediaGraph / MediaLink
 ├── Production / Playout
 ├── Protection / HA / Continuity
 ├── Synchronization / MediaTimeline
 └── Observation / Control / Query / Event
```

### 冻结不变量

- Pipeline 不得绑定到某个物理 Node。
- Workload 不得等同于一个 OS 进程。
- Node 不得被永久分配给单一功能。
- Scheduler 不得成为媒体处理器。
- Control Plane 不得承载实时媒体主路径。
- 跨 Node 的媒体必须使用显式的传输/链路语义。
- 单节点部署与分布式部署必须使用相同的领域契约。
- HA 与调度不得引入第二套 Pipeline 模型。
- Capability / Resource / Placement 必须驱动部署变化。
- 所有部署模式都必须保持信号连续性要求。

## 5. 同步

同步是一等公民的 Runtime 基础设施，涵盖时钟同步、时间戳与帧对齐。

支持的概念包括 PTP、NTP、GPS/GNSS、Genlock、Timecode、ClockDomain、Timebase、FrameSyncGroup、JitterBuffer 和 MediaTimeline。

Runtime 必须能够表示诸如 `SYNCED`、`DEGRADED`、`WAITING`、`LATE`、`DROPPED`、`UNSYNCED` 和 `RECOVERING` 之类的状态。

## 6. 制作与播出

制作切换（Production Switching）是一种专业 Runtime 能力，其模型能够容纳 M/E、PGM、PVW、Keyer、DSK、AUX、AFV、Tally、Multiview、Scene、Macro、Transition、Cut 和 Take。

播出（Playout）是一个一等公民的产品领域，包含 VirtualChannel、Playlist、Schedule、ProgramItem、PlayoutEvent、PlayoutSession、Queue、NowPlaying、Override 和 Rule。

## 7. 广播连续性

V0.3 支持在 receiver/source/card/port/pipeline/node/output/cluster 各保护级别上通用的连续性模型，包括 single、active/standby、active/active 和 N+1 模式。

首选过渡序列：
```text
Prepare New
 → Start New
 → Verify Ready
 → Fence Old
 → Atomic Switch
 → Verify
 → Stop Old
```

连续性语义仍然是 Runtime 执行的一部分，不得委托给 UI 行为。

## 8. Adapter 边界

硬件与协议厂商是 Adapter 边界之后的实现。BMD/DeckLink 是其中一种实现，而不是该架构类别本身。该抽象同样允许 AJA、Magewell、Deltacast、Network、Mobile Contribution 和 Virtual 适配器。

厂商专有的对象和 SDK 类型不得泄漏进 canonical API/领域契约。

## 9. Control / Query / Event
```text
HTTP / External Consumer
        ↓
API Boundary
   ┌────┼────┐
 Query Command Event
   ↓      ↓     ↓
Runtime Snapshot / Control Plane / Event Projection
```

API 不是 Runtime。Query 是观测，Command 表达意图，Event 记录事实。预览/媒体分发仍保持为独立的传输平面。

## 10. Standalone / Integrated

Standalone 模式是一等公民，而不是调试模式。Integrated 模式可以替换身份、注册、策略或 provider 依赖，但必须保持相同的 Runtime、领域、Command、Query 和 Event 语义。

VBMF 必须能够在不依赖母架构仓库的情况下独立构建、启动、测试、运维和部署。

## 11. 资产边界

上游 CMS/DAM 仍然是业务资产权威。VBMF 可以引用、缓存、预加载、验证就绪状态、物化 Runtime 视图、消费、执行和审计 Runtime 使用，但不得创建与之竞争的业务资产事实。

## 12. V0.3 实施原则

V0.3 的实施是增量的。顶层架构已冻结并不意味着每个领域或 API 命名空间都会在 P1 实现。

P1 先激活 standalone Runtime/Control Plane 和现有已测试的 API 契约；后续阶段在不悄然改变冻结语义的前提下增加专业能力与一致性证据。
