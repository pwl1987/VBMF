# VBMF V0.3——总体设计

> **状态：冻结基线**  
> **版本：V0.3**  
> **产品定位：专业实时媒体播出系统 / 实时媒体运行时与媒体织构**

## 1. 产品定位

VBMF V0.3 是专业实时媒体运行时与媒体织构系统。第一性职责，是可靠承担专业媒体从输入、同步、处理、制作、播出、保护、传输到输出的完整运行时生命周期，并持续提供观察、审计与恢复能力。

编码器、解码器、转码器、网关、切换器、调度器、接收器、录制器以及采集硬件，均属于本产品边界内的能力、工作负载、资源或适配器，而不是彼此平行的产品身份。

## 2. 运行时边界

```text
输入 / 贡献
    ↓
时钟 / 时间戳 / 同步
    ↓
媒体图 / 处理
    ↓
制作 / 切换
    ↓
播出 / 编排
    ↓
播出保护
    ↓
编码 / 复用 / 打包
    ↓
传输 / 网关
    ↓
输出 / 交付
    ↓
监控 / 审计 / 恢复
```

这是逻辑生命周期，不要求所有能力位于同一台机器、同一个进程或同一个厂商实现中。

## 3. 一级领域

V0.3 冻结以下 15 个专业领域：

1. 媒体输入输出
2. 媒体处理
3. 媒体网关
4. 媒体图
5. 同步
6. 制作
7. 播出
8. 播出保护
9. 传输与交付
10. 资源、工作负载与放置
11. 高可用与连续性
12. 录制、回放与时移
13. 可观测性、诊断与审计
14. 运行时控制、查询与事件
15. 资产运行时集成边界

这些是领域边界，不要求拆分为十五个服务。

## 4. 核心架构模型

```text
Runtime
 ├── Node / Device / Adapter
 ├── Resource / Capability
 ├── Workload / Placement / Allocation
 ├── Source / Input / Signal / Stream
 ├── Pipeline / MediaGraph / MediaLink
 ├── Production / Playout
 ├── Protection / HA / Continuity
 ├── Synchronization / MediaTimeline
 └── Observation / Control / Query / Event
```

### 冻结不变量

- Pipeline **不得**绑定物理 Node。
- Workload **不得**等同于操作系统进程。
- Node **不得**永久固定承担某一种功能。
- Scheduler **不得**成为媒体处理器。
- Control Plane **不得**承载实时媒体主链路。
- 跨节点媒体 **必须**通过明确的传输 / 链路语义。
- 单机与分布式部署 **必须**使用相同领域契约。
- 高可用与调度 **不得**引入第二套 Pipeline 模型。
- Capability / Resource / Placement **必须**驱动部署差异。
- 所有部署模式 **必须**满足信号连续性要求。

## 5. 同步

同步是运行时一级基础设施，覆盖时钟同步、时间戳和帧对齐。

核心概念包括 PTP、NTP、GPS/GNSS、Genlock、Timecode、ClockDomain、Timebase、FrameSyncGroup、JitterBuffer 和 MediaTimeline。

运行时必须能够表达：

```text
SYNCED
DEGRADED
WAITING
LATE
DROPPED
UNSYNCED
RECOVERING
```

## 6. 制作与播出

制作切换是专业运行时能力，可容纳 M/E、PGM、PVW、Keyer、DSK、AUX、AFV、Tally、Multiview、Scene、Macro、Transition、Cut、Take 等语义。

播出是一级产品领域，核心对象包括 VirtualChannel、Playlist、Schedule、ProgramItem、PlayoutEvent、PlayoutSession、Queue、NowPlaying、Override、Rule。

## 7. 播出连续性

V0.3 对接收器、源、卡、端口、管线、节点、输出、集群等保护层级采用统一连续性模型，支持单机、主备、双活和 N+1 等模式。

推荐切换顺序：

```text
准备新路径
 → 启动新路径
 → 验证就绪
 → 隔离旧路径
 → 原子切换
 → 验证
 → 停止旧路径
```

连续性属于运行时执行语义，不得交由 UI 自行实现。

## 8. 适配器边界

硬件和协议厂商均属于适配器边界之后的实现。BMD/DeckLink 只是其中一种实现，不是架构类别；同时允许 AJA、Magewell、Deltacast、网络、移动贡献和虚拟适配器等实现。

厂商对象和 SDK 类型不得泄漏到规范 API 或领域契约。

## 9. 控制、查询与事件

```text
HTTP / 外部消费者
        ↓
    API 边界
   ┌────┼────┐
 查询  命令  事件
   ↓    ↓     ↓
运行时快照 / 控制平面 / 事件投影
```

API 不是 Runtime。Query 表达观察，Command 表达意图，Event 表达已经发生的事实。预览和媒体交付属于独立传输平面。

## 10. 独立模式与集成模式

Standalone 是一级产品模式，不是调试模式。Integrated 可以替换身份、注册、策略或 Provider 依赖，但必须保持相同的 Runtime、领域、Command、Query 和 Event 语义。

VBMF 必须在不依赖母架构仓库的情况下独立构建、启动、测试、运行和部署。

## 11. 资产边界

上游 CMS/DAM 继续作为业务资产权威。VBMF 可以引用、缓存、预加载、验证就绪状态、物化运行时视图、消费、执行并审计运行时使用情况，但不得建立第二套业务资产事实。

## 12. V0.3 实施原则

V0.3 采用增量实施。顶层架构冻结并不意味着 P1 就必须实现全部领域或全部 API namespace。

P1 首先激活独立运行时与控制平面，以及已经经过 V0.2 测试的既有 API 契约；后续阶段再增加专业能力和一致性证据，不得静默改变已经冻结的语义。
