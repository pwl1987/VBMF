## 本次新增验证

### A. Lease 多设备排他性(防双采不变量)
容器内(`-d` 常驻)运行 `media-agent`,对 discovery 出的 3 个设备逐一 acquire,
再对 `dv0` 重复 acquire 第二个 owner:

```
device discovery complete count=3
lease acquired device=f4b077bc-ec62-5f65-977c-6943c8c7efda   (dv0)
lease acquired device=53b13018-c180-5cc7-8049-1c51dc0f6e18   (dv1)
lease acquired device=4759ae3e-3dba-53dd-a858-4580ae59fef5   (dv2)
lease re-acquire correctly rejected error=device f4b077bc... already leased
```

✅ 三个设备各自持租;同一设备重复 acquire 被 `AlreadyLeased` 拒绝 →
**排他性不变量成立**(状态机/mediasec 要求的"防 host ffmpeg / 双采")。

### B. 最简 /health (std TcpListener :8080)

容器启动参数(复刻 Option B + 端口映射):
```bash
docker run -d --name mtest --runtime=runc \
  --device=/dev/blackmagic --ipc=host \
  --cap-drop=ALL --cap-add=SYS_NICE --security-opt=no-new-privileges \
  -p 8080:8080 -v $HOME/media-agent:/media-agent:ro ubuntu:22.04 /media-agent
```

容器外(`curl http://localhost:8080/health`):
```
HTTP/1.1 200 OK
Content-Type: application/json
{"state":"ready","devices":3,"active_pipelines":0}
```

✅ 在 `cap_drop ALL` 下非特权端口(8080)正常 bind 并对外可达;
返回 `devices:3` 与 discovery 一致 → **数据贯通 discovery → health**。

## 结论

Gate 2.4 在真机验证通过:
- Health endpoint 在 Option B 隔离下可达、返回正确。

- 非特权端口 bind 在 `cap_drop ALL` 下无碍(印证 Option B 不破坏运维可观测性)。
