§1 目标与硬门（冻结·逐字）
--------------------------------------------------------------------------------
O3 目标: 找到能够同时解释 周期(~7100s)、对象、allocation family、
reservation expansion、5.5MB magnitude 的 candidate path。

六环证据硬门（逐字·缺一不可·任何 candidate 若无法形成
『候选代码路径→实际 allocation family→reservation/arena expansion→observed quantum』
证据链·不得升级为 RCA conclusion; E2 之后任何候选六环一环都不能跳）:
    candidate → allocation path → allocator behavior
    → same reservation/arena → magnitude → repeatability

C2 总原则四句式（c2rules·继承）:
  ①每层只证本层对象·不跨层升级 ②Supporting evidence 不得自动升级为本层事实
  ③相关性不得自动升级为因果性 ④为获得期望结论·不得反向扩大实验强度或修改生产系统。
解释纪律（继承）: 可写 "morphology is consistent with glibc allocator reservation
behavior"; **不得写 "this is glibc arena X"**（无 runtime evidence 前禁止单一
glibc 假说定论）。

§2 E2 判读冻结表（用户裁决逐字——分叉证据·非因果结论）
--------------------------------------------------------------------------------
前提钉死: E2 单输入变体同时改变并发度、buffer 生命周期、native allocator
pressure 等条件 ⇒ E2 最多是**候选空间分叉证据**·永不直接升级因果结论。

| E2 结果                        | 允许结论                                   | 不允许结论                |
|--------------------------------|--------------------------------------------|---------------------------|
| 单输入事件仍复现               | 双输入不是必要条件; 候选向 ingest/allocator/common path 收敛 | 不能证明某个 allocator/path |
| 单输入事件消失                 | 双输入条件是事件出现的必要条件之一; 双实例/共享 graph 候选升权 | **不能写成"双输入路径导致泄漏"** |
| 事件周期/量级改变              | workload-sensitive; 候选进入 allocation-pressure 分支 | 不能直接判定具体对象       |
| 运行异常/无法形成完整观察窗    | INCONCLUSIVE                               | 不能用异常运行作为 RCA 证据 |

E2 最终只回答一个问题（冻结句·逐字）:
  双输入/双实例条件是不是形成这条 allocation-path 的必要前提?
  是 → 沿 双实例共享 graph / make_mut / GStreamer buffer ownership 链深入;
  否 → 转向 common ingest / native allocation path·不追 program graph。
（单输入事件消失 ≠ 找到根因——只意味着双输入条件成为必要条件之一·候选权重上升·
  之后仍必须过六环硬门。）
