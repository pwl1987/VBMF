§1 观测面定义（中性层 pipeline_events::IngestAnatomy）
--------------------------------------------------------------------------------
每 (PipelineHandle) 一条，含 video/audio 两平面 + bus 计数：

IngestAnatomyPlane（probe 逐 buffer 更新）:
  buffers / bytes_total / size_min_bytes / size_max_bytes
  sizes: (size_bytes, count)[] 固定容量 8 + sizes_overflow
  meta_counts: (glib Type id, api 名, count)[] 固定容量 8 + meta_overflow
  no_pts / pts_last_ns / pts_delta_min_ns / pts_delta_max_ns / pts_backward
IngestAnatomy:
  video / audio / bus_msgs_total（bus watch 线程逐消息计数）

挂点:
  - probe: build_pipeline 后扫 elements，factory 名 decklinkvideosrc→video
    平面、decklinkaudiosrc→audio 平面，各 src pad 挂 BUFFER probe；
    recover 重建即重建（计数按管线实例重置——per-instance 视图，如实披露）。
  - register 于 build、remove 于 stop（与 HEALTH_ARCS 同生命周期律）。
  - 采样: bin 诊断分支 spawn 30s 线程，svc.log info 行
    `E4_INGEST_ANATOMY handle=N anatomy={json}`。

§2 冻结判读表（先于数据冻结；全部为相关性/排除陈述，非因果）
--------------------------------------------------------------------------------
- R-A steady（sizes 单一、meta 组成常数、buffers 速率常数 ±2%、pts delta
  稳定、pts_backward=0、bus 线性低量）⇒ 允许陈述：pad 可见逐帧分配流为
  稳态复用；"重协商 / meta 累积 / PTS 抖动 / bus 消息流" 四类 pad 可见
  异常被排除；allocation-path 环仍指 pad 面之下（插件/SDK native ×
  allocator）——六环 allocation-path 依旧未证，无 root cause 主张。
- R-B meta 累积（某 api 的 count/buffers 比值首 1/3 vs 末 1/3 漂移 >2×）
  ⇒ meta 附着链候选成立（correlation only；须过量级环）。
- R-C sizes 指纹漂移（sizes_overflow 增长或每平面 >2 个 size）⇒
  重协商/混合分配候选成立（同上，不升级）。
- R-D PTS 异常（pts_backward 增长或 delta min/max 展布 > 中位 2×）⇒
  时间戳路径候选成立（同上）。
- R-E bus_msgs_total 超线性（vs 墙钟）⇒ bus 消息流候选成立（同上）。
- 量级义务：任何候选必须给出 kB/s 估计并与已知形态对账（单输入涓流
  0.87kB/s·边界 ~1190s 迁 ~1MB；双输入离散 5.5MB 批触 @~7100s；
  每输入聚合 2.99 vs 2.81MB/h）。对不上账 ⇒ 如实登记不升级。
- 5.5MB 批触事件时窗（run_rel ~7000-7300s）内 anatomy 计数若全稳 ⇒
  批触不在 pad 可见分配流内（环仍指 native 内部）。
