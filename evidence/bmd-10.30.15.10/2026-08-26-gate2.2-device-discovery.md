## 背景

Gate 2.2 实现的是**文件系统枚举** `/dev/blackmagic/*` 节点(纯 Rust,不依赖 DeckLink SDK)。
逻辑只在 CI(无 `/dev/blackmagic`)和本地验证过编译,**未在真机验证** —— 直到本实测。

---

## 实测过程

### 1. 首次运行(暴露 bug)
```bash
scp media-agent lytv@10.30.15.10:~/media-agent
ssh lytv@10.30.15.10 "~/media-agent"
```
BMD 上 `/dev/blackmagic` 实际内容:
```
crw-rw-rw- 1 root root 10, 263 Aug 24 18:57 dv0
crw-rw-rw- 1 root root 10, 264 Aug 24 18:57 dv1
crw-rw-rw- 1 root root 10, 265 Aug 24 18:57 io0
```
程序输出:
```
device discovery complete count=0
```
**Bug:** 节点是**字符设备文件 `crw`**(主设备号 10),不是目录。原 `discover()`
逻辑 `if !path.is_dir() { continue; }` 把所有字符设备跳过了 → `count=0`。

### 2. 修复
`device.rs`:把节点判定从「是目录」改为「是字符设备」:
```rust
match entry.file_type() {
    Ok(ft) if ft.is_char_device() => {}
    _ => continue,
}
```
(重新编译:push `00c9011..7d9c952`,CI 出 artifact,download,scp,BMD 重跑)

### 3. 二次运行(通过)
```
device discovery complete count=3
media-agent skeleton loaded; interfaces frozen, logic pending
```

---

## 结论

✅ **Gate 2.2 Device discovery 在真机验证通过**:`media-agent` 在 BMD 宿主机
直接运行,正确认出 3 个 DeckLink 设备节点(`dv0`/`dv1`/`io0`),与 `/dev/blackmagic`
下的字符设备完全一致。

**这个 bug 只有在真机上才暴露** —— CI(无设备)和本地都无法发现「目录 vs 字符设备」
的假设错误。证实了「BMD 真机实测」是 Gate 2 的必要闭环,不能只靠 CI。

## 边界(诚实记录)

1. **范围:** 本次仅为**文件系统层枚举**(识别节点路径)。`model` / `serial` 仍是
   占位 `"filesystem-probe"`,真实型号/序列号需调用 `libDeckLinkAPI.so`(SDK 深度枚举),
   属后续 Gate,必须在 BMD runc 容器内实测。
2. **运行环境:** 在 BMD **宿主机**直接运行,**未**在 runc 容器内验证。容器内验证
   (Option B 隔离下 discovery 仍可用)见 `2026-08-26-gate2.2-in-container.md`(待补)。
3. **未涉及:** 信号存在性 / SDK IPC / pipeline 启动。这些在 Gate 2.5+。
