== C2 总原则（c2rules·四句冻结）==
1. 每层只证本层对象，不跨层升级。
2. Supporting evidence 不得自动升级为本层事实。
3. 相关性不得自动升级为因果性。
4. 为获得期望结论，不得反向扩大实验强度或修改生产系统。
实验纪律永久句: 「不得为获得线程归因而缩小采样间隔、延长实验或修改生产程序。」

== C2-O2 设计（注册待裁·O2 执行 NOT AUTHORIZED）==
O2-A Entry Condition: O1=RESERVATION-EXTENSION ∧ reservation identity stable ∧ RW↔PROT_NONE
conservation established —— 由既有 O1 证据核验满足（R1/R2 窗口四证全绿+conservation +0）:
**satisfied by existing O1 evidence; no O2 execution implied.**
O2-A（结构兼容性）: reservation → allocator-family structural compatibility（非 runtime arena
identification）。verdict = ALLOCATOR-STRUCTURALLY-COMPATIBLE / ALLOCATOR-STRUCTURALLY-INCOMPATIBLE
/ INCONCLUSIVE。判据①envelope size/base alignment 与典型 allocator reservation family 的结构
一致性（64MiB 对齐=支持线索）②RW 头+PROT_NONE 可增长尾 mprotect 迁移形态③[heap] 分离且平直
④libc 映射路径（既有 smaps Name）。thread/arena/core counts=仅 sanity context·不入判据。
STOP: ALLOCATOR-STRUCTURALLY-INCOMPATIBLE → 不做 thread 归因·停等重裁。
O2-B（活动相关性）: 回答「哪些线程在事件窗口内具有活动时序相关性」（activity-correlated TID
set）·不回答「哪个线程拥有 arena」。c2o2-observer = c2o1-observer v2.1 全契约继承 + ①watch 窗
per-tid {comm,stat} 采样（**保持 2s 不加快**; 核心证据=utime/stime delta+线程存在+事件窗活动;
state=辅助 supporting only）②每次触发全线程清单快照③tid 生命周期 diff。红线扩围清单（明示待批）:
task/<tid> 读取面 comm→{comm,stat}; 一次性 ldd --version/libc 版本钉扎。thread_activity_visibility
∈{VISIBLE, AMBIGUOUS, INVISIBLE} = 报告字段·非 verdict 枚举。STOP: INCONCLUSIVE(granularity) →
停·归 O3 替代证据设计。
执行序（获 O2 裁决后）: observer 实现 → 本地 fixtures（双跳+per-tid 序列+TARGET_GONE+契约 A/B/C）
→ 上盒（pgrep -x 预检·md5·runner 仅 env·2.5h 跨首事件窗）→ 镜像逐件 md5 → 离线分析（本 v2 分析器
复用+线程活动对齐）→ 登记 → 停等 O3 裁决。

== O3/O4 冻结注册 ==
O3 六阶梯度: Candidate → Temporal correlation → Allocation-path correlation → Arena correlation
→ Magnitude consistency → Repeatability。
O3 因果链硬门（逐字）: 任何 candidate 若无法形成「候选代码路径→实际 allocation family→
reservation/arena expansion→observed quantum」证据链，不得升级为 RCA conclusion（六环缺一不可）。
mgr.tick() 高频 ≠ 嫌疑成立。
O4 三态: A=Object retention（对象存活）/ B=Allocator retention（已 free·arena 留页）/
C=Fragmentation（已 free·布局不可复用）。五问: free 后 RSS 降否 / 同 arena 页可复用否 /
下次分配是否重新 commit / RSS 保持是否 allocator policy / 增长的 committed pages 是否在后续
allocation 中被重新命中。
