# Gate 2.2 — Device Discovery 容器内实测(Option B 隔离)

**日期:** 2026-08-26
**主机:** BMD `10.30.15.10`
**目的:** 验证文件系统枚举 discovery 在 **runc + Option B 加固** 容器内仍可用。
**配套:** `2026-08-26-gate2.2-device-discovery.md`(宿主机实测)、`MEDIA_RUNTIME_SECURITY_MODEL.md`(Option B 定义)

---

## 命令(复刻 Option B 隔离)

```bash
docker run --rm --runtime=runc \
  --device=/dev/blackmagic \
  --ipc=host \
  --cap-drop=ALL --cap-add=SYS_NICE \
  --security-opt=no-new-privileges \
  -v $HOME/media-agent:/media-agent:ro \
  ubuntu:22.04 /media-agent
```

> 等价于 `ops/compose.acceptance.yml` 的 `media-agent` 服务隔离参数
> (`runtime: runc` + `cap_drop: ALL` + `cap_add: SYS_NICE` +
> `no-new-privileges` + `ipc: host` + `devices: /dev/blackmagic`)。

## 结果

```
device discovery complete count=3
media-agent skeleton loaded; interfaces frozen, logic pending
```

✅ **`count=3`** —— 在 Option B 最小权限容器内,正确认出 `dv0`/`dv1`/`io0`。

---

## 结论

Gate 2.2 discovery(纯文件系统枚举)在 **runc + Option B 加固** 下工作正常。
这验证了:

1. **文件系统枚举不依赖 DeckLink SDK IPC** —— 因此 `ipc: host` 对此步非必需
   (但后续 SDK 深度枚举 model/serial 会需要,compose 已预配 `ipc: host`)。
2. **Option B 隔离不会破坏设备发现** —— `cap_drop ALL` + `SYS_NICE` + 设备白名单
   足以让 `media-agent` 读取 `/dev/blackmagic` 节点。
3. **MEDIA-SEC-01 Option B 决策得到真机验收支撑**:runc 路径下采集平面可用,
   且权限收敛到最小。
